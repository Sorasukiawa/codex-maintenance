# Codex 本地组件维护

核对实际安装与生效状态，区分官方管理、独立安装和本地定制，完成当前授权范围内的维护。默认中文汇报。

## 选择动作

- “检查”：只读盘点，给出有证据的更新、重复或清理候选。
- “按清单清理 / 更新”：读取已有清单和授权，刷新现场证据后执行，不重复确认已明确的范围。
- 新发现对象不自动加入旧清单的删除授权。只对缺少关键信息、扩大范围或授权不足的具体动作提问，其余工作继续。

优先用随附 [maintenance.py](scripts/maintenance.py) 完成重复检查。命令、状态台账和更新/回滚示例见 [脚本使用](references/automation.md)；原生查询、来源核对和清理证据见 [核对参考](references/checks.md)。不要每次重写一个临时管理器。

支持原生 Windows、macOS 和 Linux，需 Python 3.11+ 及已有 YAML 解析器。Windows 使用 PowerShell 示例与原生 Python；核对当前环境的 `CODEX_HOME`，不要把 WSL 和 Windows 安装视为同一套。junction / 重解析点按链接处理，可执行位在 Windows 上不可据此判定本地定制。

## 盘点与判定

1. 定位实际 `CODEX_HOME`、用户与系统 skills、插件版本目录和市场来源。脚本 `inventory` 只读统计这三类，记录声明名、路径 ID、哈希、调用策略、插件归属与链接。相同名字不能合并成一条；`latest` 别名不算第二个物理安装。
2. 用本机支持的原生插件列表、MCP 列表补充**有效**启停状态。脚本的缓存存在、配置声明不能证明已启用或握手成功；`unspecified` 不能写成启用。插件提供的同名 MCP 与用户覆盖项分别核对。环境变量、headers 只输出键名，启动参数和 URL 不原样展示。
3. 需要更新独立 skill 时读取 `CODEX_HOME/maintenance/registry.json`。没有来源记录就先核实安装记录或仓库；`register` 保存固定提交、完整目录基线和定制说明。登记来源是持久写入，只读审计时不顺便登记。
4. `check-updates` 只联网读取已登记仓库的目录元数据，分别显示上游目录变化、本地后续改动和本地相对上游差异。仓库提交更新但 skill 目录未变，不算组件更新。失败、未登记、来源不明分别保留为未知，不按同名搜索结果替换。

| 归属 | 处理 |
| --- | --- |
| 官方内置、官方市场、应用运行时配套的插件及其 skill/MCP | 交给所属官方机制；不手动覆盖缓存，不再安装一份独立版。用户明确要求官方渠道升级时使用原生支持的方式 |
| 来源已确认的独立版本 | 按固定提交比较整个目录，包括脚本、引用、调用策略、链接和可执行位 |
| 本地定制 | 查看实际差异，保留定制能力及策略，准备合并后的候选；差异本身不等于落后，脚本不做语义合并 |
| 疑似重复 | 比较完整能力并确认替代版实际可发现，再在授权范围内备份并移除冗余副本 |

`allow_implicit_invocation: false` 的 skill 未自动出现在上下文不是损坏。用途相近不等于重复。其他客户端、项目级入口仅在请求范围内补查；脚本不宣称全电脑覆盖。

## 执行与恢复

独立用户 skill 更新：先准备候选，`compare` 查看整目录差异；`plan` 生成精确路径、身份、哈希和调用策略预览；确认候选满足当前目标与既有授权后 `apply`。脚本仅支持真实的用户 skill 直接子目录，拒绝系统、插件及含软链接的包。遇到不支持的布局按现场证据人工维护，不重装来绕开。

执行会复核目标与候选是否变化，备份旧目录，留下操作回执。需要恢复时按操作 ID `rollback`；有后续修改则先保留并比较这些修改，不覆盖。两次目录重命名之间存在短暂缺位窗口，不在该 skill 正被其他任务修改/加载时替换；中断后先检查回执和保留目录。具体恢复边界见脚本参考。

缓存/残留清理仍按精确证据清单执行：绝对及真实路径、类型、设备/inode、内容归属、实际占用、最近写入、配置引用、打开句柄。名字像 `cache` 或 `install-*` 只用于发现候选。清理前重新核对身份和占用；检查失败或覆盖不足不能称“无占用”，活跃或被替换对象跳过。软链接分别检查链接和目标，不沿链接递归删除。记录清理前后磁盘空闲量，区分对象原占用与实际空闲变化。

禁用 MCP 的旧路径不等于垃圾，删除用户覆盖项可能启用插件同名服务。插件卸载走受支持的原生接口；对话、归档、记忆、数据库、项目及个人文件不属于组件缓存。维护台账和备份同样不是安装残留，后续清理按具体授权处理。

## 验证与交付

检查相关 YAML/TOML 可解析、入口可发现、保留组件与策略有效、清理目标确实消失。新脚本运行相关测试，技能更新验证实际行为；只读盘点不冒充业务验收。

给出已检查、已处理、未验证与原因，必要时保存精确清单、回执与恢复命令。已授权项目完成后及时交付，不因无关诊断警告扩大任务。
